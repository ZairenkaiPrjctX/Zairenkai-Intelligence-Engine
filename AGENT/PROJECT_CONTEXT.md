## Key facts and limitations

- Runtime for the spike: llama.cpp `b11500` (MIT), CPU. LiteRT-LM `v0.18.1` (Apache-2.0) was
  audited, not built. Verified. Evidence: ADR 0001.
- A 0.5B model routed 9 of 16 synthetic prompts correctly; not accurate enough alone. Verified. Evidence: `docs/SPIKE_REPORT.md`.
- No Core client: system actions stop at the preview. Verified. Evidence: `Agent.approve`, tests.
- Model distribution (2026-10-24): the app downloads the model, on the user's request, from this
  repository's release `model-<model_id>` and checks it against its manifest. The release is
  drafted by `.github/workflows/model-release.yml` from the manifest's pinned Hugging Face
  revision and published by the maintainer (`docs/MODEL_RELEASE.md`). Verified locally. Evidence:
  `tests/test_model_release.py`; `tools/model_release.py stage` on the real file, 2026-10-24.
  **Unverified**: the workflow has never run and no model release exists.
- On-device runner (2026-10-23, ADR 0002): `runtime/zie_run.cpp` on llama.cpp's core libraries
  (`b11500`), grammar `registry/output.gbnf` generated by `zie/grammar.py`; `scripts/build-android.sh`
  builds arm64-v8a and x86_64 and refuses networking imports. Verified. Evidence: Linux x86_64 host with
  the real model (FAS request → `fas.set_profile`, Indonesian temperature question →
  `thermal.snapshot`). **Unverified** on a device.
- Runtime error handling (2026-10-27): host adapters convert process-start `OSError` to
  `RuntimeUnavailable`; agent turns convert unexpected runtime and read-only executor exceptions
  to rejected/failed results without authorizing actions. Evidence: `zie/runtime.py`,
  `zie/agent.py`, and `tests/test_agent.py` (host suite passed in this change). Device behavior
  remains unverified.
